- Rust workspace 初始化 (`rust-port/Cargo.toml`, `build.rs`)
- `src/lib.rs`: 全部 `SQLITE_*` 错误码常量 + `SQLITE_OPEN_*` flag + crate 元数据
- `src/error.rs`: `SqliteError` newtype + 错误码常量 + 4 单元测试
- `src/handle.rs`: `SqliteDb` repr(C) struct 最小布局 + 2 单元测试
- `src/api.rs`: 8 个 FFI 公开函数 (libversion/close/open/open_v2/errmsg/errcode/malloc/malloc64/free) + 注释 SAFETY

## 测试

`cargo test` → 14 passed, 0 failed (3 suites: 8 lib unit + 5 integration + 1 doctest?)

## 已知限制(P0 阶段允许)

- `crate-type = ["rlib"]` 而非 `cdylib`(dylib 导出要等 L1 阶段 Pager 完成才能 stable 拼装)
- `sqlite3_malloc/free` 是桩,后续 T-0002 会替换为完整实现
- `SqliteDb` 只有 5 字段,后续 Pager/Schema/Vdbe 子任务会补到 ~600 字段

## 经验(给后续 agent)

- Rust 2024 edition 在 `unsafe extern "C" fn` 体内**仍需要显式 `unsafe { }` 块**包 `Box::from_raw` / `CStr::from_ptr` / `Layout::from_size_align_unchecked` 等
- 集成测试用 `use libsqlite_rs::sqlite3_open` 而**不是**自己 `extern "C" { fn sqlite3_open }` —— 后者会找不到符号(无 pub 链接)
- `cargo test` 第一次需要下载 + 编译 libloading 等依赖,慢(120-300s)
